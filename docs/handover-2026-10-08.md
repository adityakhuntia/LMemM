## Product target and current outcome

The MVP is an accurate, on-device project knowledge layer exposed to AI agents through
MCP. The first workflow is resuming a project: retrieve relevant work, decisions,
reasons and remaining tasks with sources. Project attachment should be automatic;
manual artifact linking is not the default. Hosted inference is an open privacy
question, never a fallback.

We now have the evidence/extraction/recall foundation and a working experimental
VS Code pilot. One live project produced a supported decision, its exact reason
and an open task from intentional notes; citations resolve to the original quotes.
This is not yet an accepted general-purpose semantic model or an agent-connected MVP.

## Two end-to-end flows

### Normal Mac companion — shared tracker

App/window/tab/timer/input triggers → display screenshot → Vision OCR/layout → activity,
content and identity rules → item memory/session timeline → notes/reminders/widget/CLI.

Existing functionality includes bounded content excerpts, stable-identity repair,
opt-in privacy-gated VS Code keyboard/cursor summaries, Ctrl+Tab/Cmd+Tab navigation
summaries, hotkey on-device dictation, attached pending notes, done/reopen controls,
return-to-item reminders and a Left/Plan widget. Typed key values are not recorded.
Latest main adds cheaper capture, smaller stored images, schema-3 storage and AI export.

Run `python lmemm.py` for the menu or `python lmemm.py start` for capture.
`python lmemm.py context --days 2` exports the rule-based AI context.
This export is not the semantic graph, and it does not establish verified decisions.

### Semantic pilot — isolated opt-in process

Approved VS Code visible file ranges / intentional notes → private source bridge →
native focused-window identity checks → SQLite source evidence → bounded episodes →
local inference → validated claims/relationships → scoped project context/citations.

Core files: `semantic_memory/store.py`, `episodes.py`, `inference.py`,
`local_runtime.py`, `relationships.py`, `retrieval.py`, `retention.py`.
Live adapter: `extensions/lmemm-source/`, `live_bridge.py`, `live_focus.py`,
`live_pilot.py`, `scripts/live_project_memory.py`.

- Canonical workspace roots anchor projects automatically; file locators identify artifacts.
- Text deduplicates while separate evidence occurrences retain time and provenance.
- The model selects numbered quote units/types. Host code supplies original IDs/text;
  validates output; rejects unknown references, invented reasons and stale commits.
- Claims distinguish observations, decisions, tasks and suggestions. Core supports
  corrections, explicit task transitions and relationships; live extraction does not
  fully exercise arbitrary contradictions, transitions or semantic associations.
- Read-only project packets include cited claims, recent excerpts and coverage omissions.
- Normal screenshot/input capture is not wired into this semantic store.

## Repairs made during live validation

1. Native focus: app-scoped Accessibility fallback when the global focused-element
   query is unavailable, preserving owner/role/secure-field validation.
2. Registration: publish revisions whenever focus invalidates intake; otherwise the
   extension keeps sending permanently stale events.
3. Publisher liveness: metadata leases survive denied intake, missing acknowledgement
   triggers re-registration, and disconnect/crash expiry is bounded.
4. Intentional note delivery: refresh authorization after the input dialog closes;
   preserve note ID/timestamp on retries; do not overwrite it with a heartbeat/snapshot;
   report local-save acknowledgement or failure. Invalid context clears pending text.
5. Command feedback: disconnected, paused and unavailable-source states explain why
   recording cannot begin instead of silently returning.
6. Scheduling: recover closed episodes lacking jobs, prioritizing notes and validating
   all evidence against current approved roots/app.
7. Cancellation: preserve actual cancellation reason on late completion; native-focus
   cancellations receive at most two persisted recovery attempts after verified focus
   returns. Pause/access/failure jobs do not automatically become focus retries.
8. Explicit `retry_notes` control recovers cancelled intentional-note work under current
   approval and existing limits. It waits for verified focus; pause clears the request.
9. Short single-line intentional `TODO:` notes use deterministic exact-source task
   parsing if the model omits/mislabels them. Document TODOs are not promoted. This is
   explicit-note parsing, not a broad improvement in semantic intelligence.

The capture privacy gate remains strict: unknown secure/non-secure text-field subroles
are denied. No fix accepts arbitrary unknown native UI to make testing easier.

## Privacy, storage and resource boundaries

The pilot reads only approved canonical local workspace sources, with trusted editor
state and matching native foreground window. Symlink/noncanonical aliases, excluded
paths, secure input and unknown context fail closed. Private bridge files have bounded
payloads, fresh timestamps, increasing sequences and per-session authorization.
There is no global keylogger or microphone in the semantic pilot.

Retained semantic data is local plaintext SQLite. Source/episode size limits and an
8-job / 128KiB queue bound work. One worker runs, local requests have a 30-second timeout
and at most two extraction attempts. Retention is scheduled at 30 days; the 250MiB
pilot allocation reserves journal/reclaim/bridge space, leaving roughly one-third
for database pages. Model weights are separate from that allocation. Runtime RAM/power
acceptance is not demonstrated by these limits.

Pause, lock/sleep, permission invalidation and stop block stale results. Deletion cleans
owned evidence and dependent support; logical deletion is not forensic SSD erasure.

**Merged regression result: 251 Python tests, including 92 semantic tests, and 6 Node
extension tests pass.** Full native suite requires macOS framework access. Tests use
synthetic sources, temporary stores, fake input events and generated OCR images.
One upstream thumbnail test emitted an unclosed-image ResourceWarning; no test failed.

Live one-project checks: registration/capture/storage/recall, stable-view dedup,
reconnect/resumed intake, saved `.env` canary exclusion, intentional-note delivery,
bounded recovery and decision/task citations. At the last acceptance checkpoint:
78 sources, 12 processed and 10 cancelled jobs. This is private local test data,
not included in Git. Some duplicate-note jobs exhausted retries and remained cancelled.

Supported recall outputs:
- Decision: `We chose SQLite because memory should stay local.`
- Reason: `memory should stay local.`
- Open task: `TODO: Test Restart Recovery`

Each resolves to an exact retained `user_note` quote. Coverage can remain truncated;
absence of a claim is not proof the work or decision did not happen.

Prior v2.4 reviewed model precision/recall: Qwen2.5 0.5B 67%/40%, Qwen2.5 1.5B 83%/100%,
Qwen3 1.7B 71%/100%. None passed the precision gate. Adapter v2.5 includes intentional
TODO parsing and requires a fresh general-quality evaluation. Keep inference explicitly
experimental. This small note test does not close general semantic acceptance.

## Reproduce and live test

1. Use macOS, install Python dependencies and Node. See README for native permissions.
   For the semantic bridge the launching terminal needs Accessibility, and VS Code
   must expose editor accessibility (Accessibility Support On worked in the live test).
2. Run automated checks from this feature checkout:

```bash
python -m unittest discover -s tests
node --test extensions/lmemm-source/bridge.test.js
```

In the existing isolated worktree, use `../../.venv/bin/python` instead of `python`.
The tests do not require running the Ollama service.

3. Follow [live-semantic-pilot.md](live-semantic-pilot.md) for evidence-only startup,
   explicit experimental-model startup and local runtime configuration. Cached model
   weights and `data/runtime-1.5b.json` are intentionally not committed. The collector
   never downloads models or starts the model service.
4. Launch a VS Code development host with `--extensionDevelopmentPath` pointing to
   `extensions/lmemm-source`; run **LMemM: Connect Experimental Project Memory** and
   provide `<pilot-data-dir>/bridge/grant.json`. Wait for the verification tab to close.
5. Open an approved README, scroll/change visible content, then record separate harmless
   decision and TODO notes. Wait for **project note saved locally** after each. For a
   fresh episode, leave the editor focused for about 2.5 minutes (two-minute episode
   duration plus extraction). Inspect context after that; do not repeatedly resubmit.
6. Use CLI controls below with the same data directory. Sleep/lock requires explicit
   resume. Pause does not auto-resume just because focus returns.

```bash
python scripts/live_project_memory.py --data-dir data/live-pilot status
python scripts/live_project_memory.py --data-dir data/live-pilot resume
python scripts/live_project_memory.py --data-dir data/live-pilot retry_notes
python scripts/live_project_memory.py --data-dir data/live-pilot context --project "$PWD" --days 2
python scripts/live_project_memory.py --data-dir data/live-pilot pause
python scripts/live_project_memory.py --data-dir data/live-pilot stop
```

`retry_notes` is explicit and bounded; returning to verified editor focus permits
processing. No need to retry after a supported claim already exists. Do not share
`grant.json`, tokens, databases or captured user content in commits/debug attachments.

## Recommended next order

1. Benchmark representative enabled-worker and normal-capture sessions: CPU/RAM/power,
   retention pressure, sleep/restart, exclusions and two approved projects.
2. Fresh semantic/privacy evaluation: distinguish observed documents from user work,
   improve precision and corroborated associations; validate v2.5 against new heldout data.
3. Build permissioned browser evidence and website-level access controls. Treat switching
   patterns as weak signals, not proof that tabs belong to a project.
4. Expose scoped read-only `project_context`/citation resolution through MCP; validate
   an agent resuming a real project without widening capture access. Keep experimental
   claims and coverage visible. This is the first agent-facing product step.
5. Richer automatic relationships and resource optimization informed by actual tests.
   Graph UI, broad cross-agent persistence and hosted inference follow the scoped MVP.
