# Labels: a short plain-English summary per settled thing, from your laptop's Claude

**Date:** 10 October 2026 · **Branch:** `labels/claude-cli-reducer` · **Status:** built and tested off-Mac; not yet run against a live tracker.

## Why
Rules and OCR say *which* thing you were on. A label says what it was *about* (summary, kind, project guess, entities), so the context export and the future MCP carry meaning, not only raw excerpts. Aditya's constraints: no heavy CPU, no local model yet, use the laptop's Claude, **tokens are the most important cost**, never send screenshots, and tell the model the app, where the pointer is, and the text.

## What it does
`python3 lmemm.py label` sends settled things in batches to `claude -p` and stores answers in `memory/labels.json` (separate from `memory.json`, so it never races the tracker). `context.py` adds `summary`, `summary_by`, `entities`, `open_question` to a thing when a label exists. `label --dry-run` prints exactly what would be sent and the token estimate; `label --status` shows today's use.

## What the model sees (text only)
Per thing: app, window title, page (host + path, query stripped), focus (the focused control's label), pointer (plain words: `near the heading "Pricing"`), activity, the text nearest the pointer first, then only the lines that are new since the last label, open notes, the previous summary. Capped at 1,200 characters (~300 tokens). Secret-looking lines are dropped (same rule as the event trail); text cannot close the data marker; the instruction says captured text is data, not commands. The pointer/focus words are saved on the item by `labels.note_where` (called from `Tracker.remember`).
Never sent: screenshots; things from Messages/Mail/WhatsApp/Signal/Telegram/Slack/Teams/Discord or of kind chat/email (`LABEL_OFF_APPS`, `LABEL_OFF_KINDS`, default off); anything the tracker already skipped.

## Token control
- Only *settled* things (unchanged 120 s) with new text since their last label, worked on 20 s+ (or pinned / noted / 2 min+).
- Batches of up to 15 per call: the CLI's own fixed cost is **~2.4k tokens per call (measured here with `--system-prompt`, `--tools ""`, no MCP, no session, empty working folder)**, so one batch pays it once. A real 3-thing batch cost 3,283 tokens.
- Daily cap `LABEL_DAILY_TOKENS = 50000`, counted from the CLI's own `usage` (cached reads count a tenth). At 80% only high-value things are sent; at the cap nothing is, and the command says so. Batches shrink to fit what is left.
- `--effort low`, `--model haiku`; no `--json-schema` (it added a second turn and thinking tokens); the reply is validated in Python, bad rows dropped.
